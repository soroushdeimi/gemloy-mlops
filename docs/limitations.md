# Limitations and open verification

No deployment, remote login, host API call, weight download, cluster query, image publication, commit or push was performed. All local tests use a mocked upstream. Both the new WSL test node and the native alternative, their runtimes and the complete GitOps reconciliation remain unverified.

The alternative vLLM checkpoint and tagged software implementations were verified through public documentation/source. This does not establish successful kernel execution or acceptable summarization quality on an RTX 3090. The full serialized checkpoint size informs the weight budget, but runtime repacking and allocator overhead can differ. Actual allocator use, cache capacity, cold start, CUDA/driver compatibility and correctness require the real card. Eager serving reduces graph overhead but may sacrifice throughput. CUDA sample image availability, entrypoint execution and NVML tooling also require a real image pull and Job run.

The default test path is a separate WSL2 Ubuntu 24.04 distro, not the existing serving distro. GPU Operator is not supported for this WSL2 path and is excluded from active GitOps. DCGM exporter is not used on WSL2; the nvidia-smi exporter supplies temperature, memory and utilization instead. Standalone device-plugin NVML discovery, allocation, runtime injection and the CUDA Job are experimental and **not verified**. We will try the pinned standalone plugin and stop at a failed allocation/Job gate; CUDA support alone does not prove Kubernetes GPU support. Windows owns the driver; Linux display-driver installation is prohibited. See test-env-wsl.md for exact operator steps and restoration. Native Ubuntu with GPU Operator remains an alternative topology. Missing telemetry must not be treated as zero or healthy.

The existing GGUF served successfully on this GPU in the Windows host deployment, but the production-build CUDA image tags were unavailable in the registry. The test pins a verified newer Linux image; its memory fit at the production context, behavior, flags, throughput and quality remain unverified. The hostPath file must already exist with the specified byte size; neither chart initialization nor the test procedure downloads weights. File-size verification is not integrity verification. Read-only mounts protect the container path but do not prevent a Windows process from replacing the underlying file. Do not update weights during the test. Drive mounts and persistent state on WSL may be slower or disappear after restart; verify them before every model start.

The pinned llama.cpp metrics do not include KV occupancy/context fraction or native latency histograms. The llama.cpp dashboard and alerts use only available counters/gauges. The vLLM alternative retains the richer KV/latency contract. When DCGM cannot run (WSL2), GPU temperature, memory and utilization come from the nvidia-smi exporter; XID faults are DCGM-only and have no data there.

One control plane, one GPU and local-path storage provide no high availability. A node loss interrupts inference and its cache. A model upgrade uses Recreate and causes downtime. App HPA does not remedy GPU saturation. The broader multi-GPU/KEDA and MIG designs are proposals, not installed controllers or tested manifests.

Kubeconform runs with strict core validation and the required ignore-missing-schemas option. Custom resources without schemas are skipped; Helm rendering and promtool syntax checking do not replace CRD admission or live metric validation. Upstream monitoring and GPU Operator charts were pinned but not installed or downloaded during this work. Support-matrix and integration checks remain commissioning tasks.

CI is defined but has not run on the eventual repository. GHCR access, branch protections, workflow-bot write access and Argo credentials require operator setup. Example repository/image paths must be replaced before syncing. The ciphertext example is deliberately invalid and excluded from synced paths. No real sealed token was created; controller-key backup and recovery must be tested. Automated notifications, public TLS/authentication, ingress rate limits and network-policy hardening require site policy before public exposure.

The app limits input by character count, not exact model tokens; a token-heavy prompt may exceed context and return 422 when the upstream 400 identifies context/token length; unrelated upstream client errors remain 502. It returns whole responses rather than streaming. Request bodies and responses are not logged. Retry of a server error can repeat inference work if the upstream completed before failing; retries are bounded but do not provide exactly-once execution. App metrics assume a single worker per pod, as configured in the Docker command.

Tool installation uses pinned release URLs and package versions but has no complete transitive lockfile or release-digest verification. Driver/toolkit package patches follow Ubuntu/NVIDIA repositories. Record exact installed versions and image digests before a reproducibility claim across time. Metrics retention, alert thresholds, resource reservations and probe budgets are initial policies with calculations in the design/monitoring docs; they require measurement.

The local Docker build gate could not run because the Docker daemon socket was unavailable. The build command and error are recorded in the report. An actual image build and container startup remain required in CI or a Docker-enabled test environment. Screenshots are intentionally absent until a deployment supplies real telemetry.
